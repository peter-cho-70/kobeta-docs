## 1. 프로젝트 개요

KBTE(한국방송기술교육원, 커밋 이력상 이후 **KOBETA**로 명칭 통일)의 교육 운영 업무를 지원하는 사내 웹 도구입니다. 기획 단계에서 두 개의 PRD가 나왔고, 실제 구현은 그중 하나에 집중되어 있습니다.

- **교육 커리큘럼 설계 플랫폼** ([`docs/product/PRD_curriculum.md`](product/PRD_curriculum.md)) — 실제로 구현이 진행된 축. 교육분야/강사/운영담당자 마스터데이터, 과정 카드 Pool, 드래그앤드롭 커리큘럼 빌더가 핵심.
- **쇼츠 제작 플랫폼** ([`docs/product/PRD.md`](product/PRD.md)) — 데이터 모델(`ShortsProject`, `ShortsTemplate`, `ShortsClip` 등)과 화면 뼈대(`/shorts/projects`, `/shorts/templates`)만 만들어졌고, PRD의 핵심인 AI 분석·서버사이드 렌더링 파이프라인은 아직 없음.

기술 스택: Next.js(App Router) + Prisma 7 + Neon Postgres(서버리스) + Vercel Blob(파일 저장) + Vercel 배포. 자세한 데이터 저장 구조는 `app/README.md` 참고.

## 3. 알려진 이슈 / 리스크 (현재 시점 기준)

git 이력과 코드에서 확인했거나, 아직 반영되지 않은 것으로 보이는 항목입니다. 실제 해결 여부는 직접 확인이 필요합니다.

- **로컬 개발 = 운영 데이터 공유**: `app/README.md`에 명시된 대로, 로컬 `npm run dev`도 배포 환경과 동일한 Neon Postgres/Vercel Blob을 사용합니다. 로컬에서 실험적으로 데이터를 추가/삭제하면 실제 운영 데이터에 바로 반영되므로, 테스트용 별도 DB 브랜치(Neon은 브랜치 기능 지원) 분리를 검토할 필요가 있습니다.
- **자동화 테스트 부재**: `package.json`에 테스트 스크립트가 없고 테스트 디렉토리도 없습니다. 지금까지는 Playwright MCP로 수동 브라우저 확인만 해온 것으로 보입니다(삭제한 `.playwright-mcp/` 로그가 그 흔적).
- **PRD.md(쇼츠 플랫폼)와 실제 구현의 괴리**: 데이터 모델과 화면은 있지만, PRD가 요구하는 AI 하이라이트 추천, 스마트 리프레임, STT 기반 자막 자동화, ffmpeg 서버사이드 렌더링/출력 파이프라인은 확인되지 않습니다. 현재 상태가 "스텁"인지 "부분 구현"인지는 `src/app/shorts/`, `src/lib/shorts/` 코드를 직접 검토해 확인이 필요합니다.
- **PRD_curriculum.md Phase 2~4 미구현 확인**: 강사료 등급/예산 자동산정(`FeeGradeTable`, `BudgetLine`), 성과지표(KPI) 관리, 사업(Program) 계층, 사업계획서 자동 생성 관련 Prisma 모델이 현재 스키마(`app/prisma/schema.prisma`)에 없습니다 → 4장의 "다음 단계"를 참고.
- **개인정보 처리 원칙**: PRD_curriculum.md 12장에서 "기관현황/인력현황에 주민등록번호 등 식별번호를 저장하지 않는다"는 원칙을 명시했습니다. 강사(`Instructor`) 등 개인정보를 다루는 기능을 늘릴 때 이 원칙이 지켜지는지 주기적으로 점검이 필요합니다.

## 4. 향후 개발 방향

`docs/product/PRD_curriculum.md` 9장 로드맵을 기준으로, 이미 만들어진 것(Phase 1 대부분)과 아직 남은 것을 구분합니다.

**이미 구현된 것으로 확인됨 (Phase 1 범위)**
- 카테고리/강사/운영담당자 마스터데이터, 과정 Pool, 드래그앤드롭 빌더(커스텀 슬롯·시간 편집·충돌 감지 일부), 인쇄 출력

**다음으로 검토할 것**
1. **AI 자동 커리큘럼 초안 생성** (PRD_curriculum 4.4) — 주제/기간/장소만 입력하면 Pool에서 조합해 초안을 만들어주는 기능. 이미 트렌드 분석에 Gemini 연동 경험이 있어 재사용 가능.
2. **강사 일정 안내 이메일 자동화 + 예산/강사료 자동산정** (4.5, 4.9) — 강사료 등급표(`FeeGradeTable`) 마스터부터 필요.
3. **교육 안내문(공문) PDF 자동 생성** (4.8) — Pool·빌더 데이터를 실제 KOBETA 표준 양식으로 내보내는 기능. `docs/curriculum-data/`의 2022년 보고서·안내서 포맷이 그대로 템플릿 참고 자료가 됨.
4. **사업(Program) 계층 + 성과지표(KPI) 관리 + 사업계획서 자동 생성** (4.9~4.12) — 범위가 크므로 별도 설계가 필요. `Program`, `KPIIndicator`, `BudgetLine`, `OrganizationProfile` 등 5장 데이터 모델 초안이 이미 PRD에 있음.
5. **쇼츠 플랫폼 재개 여부 결정** — 현재 데이터 모델만 있는 상태이므로, 실제로 이 축을 계속 개발할지(AI 분석/렌더링 파이프라인 구축) 아니면 커리큘럼 플랫폼에 집중할지 우선순위 결정이 필요.
6. **테스트 체계 도입** — 최소한 API 라우트(카테고리/강사/빌더 저장) 대상 스모크 테스트부터 시작하는 것을 권장.
7. **로컬/운영 데이터 분리** — Neon 브랜치 기능으로 로컬 개발용 브랜치를 분리해, 로컬 실험이 실 운영 데이터를 건드리지 않도록 개선.
