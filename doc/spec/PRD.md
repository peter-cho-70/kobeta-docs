# PRD: KBTE 쇼츠 제작 플랫폼

**문서 버전**: v0.1 (초안 제안)
**작성일**: 2026-06-19
**작성 대상**: 한국방송기술교육원(KBTE) 콘텐츠 제작팀
**참고 자료**: 자막 템플릿 에디터 UI 스크린샷 (배경/로고/제목/비디오/고정텍스트/캡션/폰트 탭 구조)

---

## 1. 배경 및 목표

KBTE는 교육 프로그램 및 다시보기(VOD) 콘텐츠를 유튜브 쇼츠, 인스타그램 릴스, 틱톡, 카카오TV 등 다채널에 맞춰 숏폼으로 재가공하고 있습니다. 현재는 NLE(프리미어 등)를 활용한 수작업 편집에 의존하고 있어 다음과 같은 문제가 있을 것으로 예상됩니다.

- 동일한 원본(긴 강의/방송 다시보기)에서 매번 하이라이트 구간을 수동으로 찾아야 함
- 플랫폼별 규격(길이, 화면비, 자막 스타일)에 맞춰 반복 작업이 발생
- 자막 스타일(폰트, 강조색, 고정 텍스트, 로고 위치 등)이 영상마다 들쑥날쑥할 위험
- 기획-자료수집-편집-자막-배포가 분절된 도구/프로세스로 진행되어 협업 추적이 어려움

**제품 목표**

1. 영상/이미지/오디오/문서/텍스트 등 어떤 소스로든 30초·1분 세로형 쇼츠를 일관된 워크플로우로 제작
2. 업로드 화면처럼 템플릿화된 자막/디자인 시스템으로 브랜드 일관성 확보
3. AI를 활용해 "찾고 자르고 자막 다는" 반복 노동을 보조 자동화 — 단, 최종 판단은 항상 사람이 함
4. MP4(H.264/H.265) 표준 출력으로 모든 플랫폼에 호환되는 영상 생성
5. 기획→배포까지 한 화면에서 추적 가능한 프로젝트 단위 관리

## 3. 전체 제작 워크플로우 (7단계)

```
① 기획 → ② 자료 → ③ AI 분석/추천 → ④ 편집 및 출력 → ⑤ 수정/후반작업 → ⑥ 자막작업 → ⑦ 최종 배포
```

| 단계 | 목적 | 핵심 산출물 | AI 개입도 |
|---|---|---|---|
| ① 기획 | 쇼츠 방향성·타깃·규격 결정 | 기획서, 후킹 카피 초안 | 중 (초안 제안) |
| ② 자료 | 원본 소스 업로드/정리 | 미디어 라이브러리 | 낮음 |
| ③ AI 분석/추천 | 하이라이트·컷·음악·리프레임 추천 | 추천 컷 리스트, 스크립트 | 높음 (제안만, 확정은 사람) |
| ④ 편집/출력 | 타임라인 편집, 1차 렌더링 | 편집본 v1 (MP4) | 낮음 |
| ⑤ 수정/후반작업 | 검수, 컬러/오디오 보정, 버전관리 | 승인된 최종 편집본 | 낮음 |
| ⑥ 자막작업 | 템플릿 기반 캡션/디자인 적용 | 자막 완성본 | 중 (자동 타이밍/하이라이트 추천) |
| ⑦ 최종 배포 | 메타데이터 생성, 채널별 업로드 | 배포된 콘텐츠 + 성과 추적 | 중 (해시태그/제목 추천) |

## 4. 단계별 상세 기능 요구사항

### 4.1 기획 (Planning)

- **프로젝트 생성 마법사**: 목표 길이(30초/1분), 대상 플랫폼(유튜브쇼츠/릴스/틱톡/카카오TV — 다중 선택 가능), 톤앤매너(정보전달형/하이라이트형/티저형) 선택
- **원본 연결**: 긴 다시보기 영상, 강의 문서(PPT/PDF), 녹음 파일을 프로젝트에 연결
- **AI 기획안 초안**: 원본 길이가 길 경우(예: 1시간 강의), AI가 핵심 구간 후보와 제목·후킹 멘트 초안을 자동 생성하여 PD가 선택/수정
- **기획서 템플릿**: 제목, 후킹 멘트, 핵심 메시지, CTA, 해시태그 초안을 한 화면에서 정리

### 4.2 자료 (Materials)

- **지원 포맷**
  - 영상: mp4, mov, mkv, webm
  - 이미지: jpg, png, webp, gif
  - 오디오: mp3, wav, aac, m4a
  - 문서: pdf, docx, pptx, txt, md (텍스트 추출 + 슬라이드 이미지화)
  - 직접 텍스트 입력 (자막/카드뉴스형 컷 제작용)
- **미디어 라이브러리**: 폴더/태그/검색, 즐겨찾기, 사용 이력 표시
- **자동 메타데이터 추출**: 영상 길이/해상도/코덱/프레임레이트, 이미지 EXIF, 문서 텍스트(필요 시 OCR)
- **저작권 무료 음원 라이브러리**: 스크린샷의 디자인 철학과 동일하게 CC0/퍼블릭도메인 음원을 큐레이션 탭으로 제공, 출처/라이선스 정보 자동 기록

### 4.3 AI 분석 및 추천 서비스 (핵심 차별화 포인트)

이 단계가 본 제품의 경쟁력입니다. 모든 추천은 **제안(suggestion)**이며 사용자가 100% override 가능해야 합니다.

- **STT 기반 스크립트 자동 추출**: 음성을 텍스트화하고 단어 단위 타임코드 동기화 (자막 작업 단계의 기초 데이터로 재사용)
- **하이라이트 구간 자동 탐지**: 키워드 반복/강세, 발화 속도 변화, 장면 전환, 슬라이드 전환 시점을 분석해 30초/1분 분량에 맞는 컷 후보 3~5개 제시
- **스마트 리프레임**: 16:9 원본을 9:16 세로로 변환할 때 얼굴/주요 객체를 추적해 자동 크롭 (수동 크롭 대비 시간 절감)
- **음악 추천**: 영상의 분위기/템포를 분석해 CC0 라이브러리에서 어울리는 BGM 매칭, 비트 동기화 컷 제안
- **캡션 하이라이트 키워드 자동 추천**: 스크립트에서 핵심 단어를 골라 강조색 후보 제시 (스크린샷의 노란색/주황색 강조 캡션과 동일한 개념)
- **메타데이터 자동 생성**: 플랫폼별 제목/설명/해시태그 초안 (SEO 고려)

### 4.4 편집 및 출력 (Editing & Export)

- **타임라인 에디터**: 멀티 트랙(비디오/이미지, 배경음악, 효과음, 텍스트/캡션, 로고/워터마크)
- **패스트컷 편집 프리셋**: 컷 간격, 트랜지션, 배속 등을 스타일 프리셋으로 일괄 적용
- **실시간 9:16 미리보기**: 스크린샷 좌측 프리뷰 패널과 동일한 컨셉의 캔버스
- **출력 사양**
  - 컨테이너: MP4
  - 코덱: H.264(libx264, yuv420p) 기본 / H.265(libx265, HEVC) 옵션
  - 해상도: 1080×1920 기본 (필요 시 720×1280 경량 옵션)
  - 오디오: AAC
  - 비트레이트 프리셋: 고화질/표준/용량절약
- **플랫폼별 내보내기 프리셋**: 유튜브쇼츠/릴스/틱톡/카카오TV 각각의 길이·화면비·용량 제한에 맞춘 자동 변환

### 4.5 수정 및 후반작업 (Revision & Post-production)

- **버전 관리**: 수정 이력 저장, 특정 버전으로 되돌리기
- **검수/승인 워크플로우**: 강사/출연진 코멘트, PD 승인 단계 (교육기관 콘텐츠 특성상 검수 절차가 중요할 것으로 판단)
- **기본 보정 툴**: 오디오 노멀라이즈/노이즈 제거, 색보정 프리셋
- **인트로/아웃트로/워터마크 일괄 적용**

### 4.6 자막 작업 (업로드 UI 기반 상세 설계)

업로드해 주신 화면이 정확히 이 단계의 핵심 기능입니다. 아래는 해당 UI를 그대로 시스템 설계로 옮긴 내용입니다.

**템플릿 관리 구조**
- 템플릿 선택(드롭다운) / 새 템플릿 생성 / 이름 변경 / 저장 / 삭제
- 템플릿은 프로젝트 간 재사용 가능 (KBTE 채널 전체의 톤앤매너 통일에 활용)

**템플릿 구성 탭 (7개)**

| 탭 | 설정 항목 |
|---|---|
| 배경 | 이미지 배경 / 단색 배경, 프리셋 컬러 8종 + 커스텀 컬러피커 |
| 로고 | 위치(상/하/좌/우), 크기, 투명도, 노출 시간(전체/인트로만) |
| 제목 | 폰트, 크기, 색상, 정렬, 등장 애니메이션 |
| 비디오 | 메인 영상 프레임의 위치/크기/모서리 둥글기/그림자, 16:9 원본의 9:16 내 배치 방식 |
| 고정 텍스트 | 항상 노출되는 안내문구(워터마크성 텍스트), 줄바꿈 시 영역 자동 확장 규칙 |
| 캡션 | 자동 생성 캡션 스타일 — 기본색/하이라이트색/사용자 지정색, 줄바꿈 규칙, 캡션 미리보기 |
| 폰트 관리 | 한글 폰트 업로드, 라이선스 정보 기록(무료 폰트 출처 명시 권장) |

**자막 작업 흐름**
1. AI 분석 단계에서 생성된 스크립트 + 타임코드를 자막 트랙에 자동 배치
2. AI가 추천한 키워드에 하이라이트 색상 자동 적용 → PD가 검토 후 확정/수정
3. 단어/구간 단위로 타임코드 미세 조정 (스크린샷의 "캡션 미리보기" 영역처럼 실시간 미리보기 제공)
4. 줄바꿈 규칙: 한 줄 기준 글자 수 초과 시 자동 두 줄 처리 (스크린샷에 명시된 동작과 동일)
5. 템플릿 적용 시 배경/로고/제목/고정텍스트가 일괄 반영되어 최종 디자인 완성

### 4.7 최종 배포 (Distribution)

- **플랫폼 연동**: 유튜브 데이터 API(쇼츠 업로드 + 메타데이터), 인스타그램/틱톡/카카오TV는 API 정책에 따라 자동 업로드 또는 "다운로드 + 가이드형 수동 업로드" 지원
- **예약 배포**: 채널별 업로드 일정 스케줄링
- **해시태그/제목 자동 생성**: AI 추천 메타데이터를 배포 직전 최종 확인
- **성과 트래킹 대시보드**: 조회수/좋아요/완주율 등 API로 수집 가능한 지표 시각화 (Phase 2 이후)
- **다국어 자막 옵션**: 해외 확산을 염두에 둔 자동 번역 자막 (Phase 3 이후 제안)

## 5. 비디오 처리 파이프라인 (기술 상세)

브라우저 단독 렌더링(WebCodecs, ffmpeg.wasm)은 H.265 인코딩이나 1분 이상의 멀티트랙 합성에는 속도/메모리 한계가 뚜렷하므로 **서버사이드 렌더링**을 권장합니다.

```
[클라이언트: 편집 상태(JSON) 전송]
        │
        ▼
[API 서버: 렌더링 작업(Job) 생성 → 큐 등록]
        │
        ▼
[작업 큐: Redis + BullMQ 또는 Celery]
        │
        ▼
[렌더링 워커: ffmpeg 실행 (오토스케일 가능)]
        │
        ▼
[오브젝트 스토리지 업로드 → 완료 알림(WebSocket/Push)]
```

**ffmpeg 출력 예시**

```bash
# H.264 (기본, 호환성 최우선)
ffmpeg -i input.mp4 \
  -c:v libx264 -profile:v high -pix_fmt yuv420p -crf 20 -preset fast \
  -c:a aac -b:a 128k \
  -movflags +faststart \
  output_h264.mp4

# H.265 (용량 최적화, 옵션 제공)
ffmpeg -i input.mp4 \
  -c:v libx265 -tag:v hvc1 -pix_fmt yuv420p -crf 24 -preset medium \
  -c:a aac -b:a 128k \
  -movflags +faststart \
  output_h265.mp4
```

> **주의**: H.265 출력 시 반드시 `-tag:v hvc1`을 지정해야 Safari/iOS 호환성이 보장됩니다(`hev1` 태그는 일부 환경에서 재생 불가). 기본 출력은 H.264로 두고, H.265는 "용량 절약 옵션"으로 안내하는 것을 권장합니다.

GPU 가속(NVENC)은 처리 속도를 크게 높이지만 비용과 인프라 복잡도가 증가하므로, 초기에는 CPU 인코딩(libx264/libx265) + 오토스케일링 워커로 시작하고 트래픽이 늘어나면 GPU 도입을 검토하는 단계적 접근을 제안합니다.

## 6. 시스템 아키텍처 제안

| 영역 | 제안 기술 | 비고 |
|---|---|---|
| 프론트엔드 | React + 타임라인 에디터(자체 구현 또는 Remotion 활용 검토) | 9:16 실시간 미리보기 필수 |
| 백엔드 API | Node.js 또는 Python(FastAPI) | 프로젝트/템플릿/미디어 CRUD |
| 렌더링 워커 | ffmpeg + 작업 큐(Redis/BullMQ 또는 Celery) | 수평 확장 가능 구조 |
| 스토리지 | S3 호환 오브젝트 스토리지 | 원본/중간산출물/최종본 분리 보관 |
| 데이터베이스 | PostgreSQL | 프로젝트, 템플릿, 사용자, 자막 데이터 |
| STT/AI 분석 | Whisper(STT) + LLM(하이라이트 추천, 메타데이터 생성) | Claude API 등 활용 검토 |
| 컴퓨터비전 | 얼굴/객체 추적 모델 (스마트 리프레임용) | 오픈소스 모델 우선 검토 |
| 인증 | KBTE 내부 SSO 연동 검토 | 외부 협업자용 별도 권한 체계 |

## 8. 비기능 요구사항

- **성능**: 1분 영상 1080×1920 H.264 기준, 워커 1대당 렌더링 시간 목표 설정(예: 실시간 대비 2~3배 이내)
- **보안/권한**: 프로젝트 단위 접근 권한, 미공개 원본(강의 다시보기 등) 외부 유출 방지
- **확장성**: 작업 큐 기반으로 동시 다중 프로젝트 렌더링 처리
- **접근성**: 캡션 색상 대비(WCAG 고려), 색약 사용자 고려한 강조색 기본값 점검
- **저작권 관리**: 음원/폰트 사용 시 출처와 라이선스 정보를 프로젝트에 자동 기록 (배포 전 체크리스트화)

## 10. 추가 제안 아이디어 (제 의견)

요청하신 구조에 더해, 실제 운영 시 도움이 될 만한 아이디어를 제안드립니다.

1. **"긴 영상 → 다중 쇼츠" 일괄 추출**: KBTE의 다시보기 콘텐츠 특성상, 1시간 강의 하나에서 30초 쇼츠 5~10개를 한 번에 후보로 뽑아주는 배치 기능이 특히 유용할 것으로 보입니다. AI 분석 단계의 핵심 가치로 발전시킬 만합니다.
2. **챕터/슬라이드 기반 컷 추천**: 강의 자료(PPT)가 함께 업로드되는 경우, 슬라이드 전환 시점과 발화 내용을 매칭해 "이 슬라이드 설명 구간"을 통째로 쇼츠 후보로 제안하는 기능.
3. **퀴즈형 캡션 템플릿**: 교육 콘텐츠 특성을 살려, "정답 공개 전 일시정지" 같은 인터랙티브 캡션 패턴을 템플릿에 추가하면 교육 채널 특화 기능이 됩니다.
4. **템플릿 버전 잠금**: 배포된 영상에 사용된 템플릿이 이후 수정되어도 과거 영상에는 영향이 없도록 템플릿 스냅샷을 함께 저장.
5. **음원/폰트 라이선스 체크리스트**: 배포 직전 "사용된 모든 음원/폰트가 라이선스 조건을 충족하는지" 자동 점검하는 게이트.
6. **협업 코멘트 핀**: 영상 특정 타임코드에 코멘트를 남기는 기능(검수 단계에서 출연진/PD 간 소통 효율화).
7. **A/B 썸네일 자동 생성**: 한 쇼츠당 대표 프레임 후보 3컷을 AI가 추출해 PD가 고르도록 제안.

## 11. 리스크 및 고려사항

- AI 하이라이트 추천의 정확도는 콘텐츠 장르(강의 vs 인터뷰 vs 시연)에 따라 편차가 클 수 있어, 초기에는 "추천 + 인간 최종 확정" 구조를 반드시 유지해야 합니다.
- 렌더링 서버 비용은 동시 사용자/영상 길이에 비례해 증가하므로, MVP 단계에서부터 큐 기반 처리량 모니터링 체계를 마련하는 것이 좋습니다.
- 플랫폼(유튜브/인스타/틱톡) API 정책은 자주 변경되므로, 자동 업로드 기능은 실패 시 수동 업로드로 자연스럽게 전환되는 폴백을 설계해야 합니다.
- 폰트/음원 라이선스 누락은 배포 후 법적 리스크로 이어질 수 있어 8장에서 제안한 라이선스 체크리스트를 MVP 범위에 포함하는 것을 권장합니다.
